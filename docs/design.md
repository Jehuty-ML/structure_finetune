# 设计说明

## 问题

小模型适合端侧语音伙伴，但产品需要一次生成同时给出：

1. **口播文本**（给人听）
2. **控制字段**（给 App / TTS / 状态机）

纯 Prompt 在 1.7B～8B 上不稳定；需要固定契约 + SFT。

## 契约形态（v3）

```text
<think>…</think>     ← 可剥离；不进 TTS
[json]{…}[/json]     ← 唯一 Schema 校验的机器契约
```

已删除：

- 自由文本 `<state>`（与 JSON 韵律重复，不可 Schema 约束）
- 自由文本 `<abstract>`（多轮记忆改由客户端历史 / Prior 行承载）

机器控制信号（`intent` / `ui_mode` 等）全部进 JSON。`[json]` 定界标签让块边界与 `<think>` 一致，解析更稳。

## 解法形态

1. 冻结契约（文档 + JSON Schema），数据 / 训练 / 评测 / 服务共用  
2. SFT 把契约焊进小模型权重  
3. 同一解析器做门禁与评测  
4. 多轮上下文由客户端拼接历史，不额外要求模型写记忆块  

## 可移植性

换 Schema 与 system prompt，即可用于工具路由、游戏状态机、IoT「边说边控」。不变式仍是：**小模型 + 固定契约 + SFT + 共用校验器**。
